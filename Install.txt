1. ÜBERSICHT
================================================================================

R+MUNI läuft auf Windows 11 und Linux ohne Datenbankserver, Webserver oder
Container. Alle Komponenten sind kostenlos und open source.

Entwickelt und getestet auf Windows 11 Enterprise.
Linux theoretisch kompatibel — alle Scripts verwenden os.path (keine hardcodierten
Pfade), noch nicht offiziell getestet.
macOS theoretisch kompatibel, noch nicht offiziell getestet.

Wer R+MUNI auf Linux oder macOS testet ist herzlich eingeladen Feedback zu geben —
Erfahrungsberichte fließen in die Dokumentation ein.


1.1 Verzeichnisstruktur
--------------------------------------------------------------------------------
Alle R+MUNI Verzeichnisse erhalten ein Kürzel (max. 4 Zeichen) als Suffix.
Dir_Setup.bat legt die Struktur automatisch an — Kürzel wird beim Start abgefragt.
Bindende Referenz für alle Verzeichnisdetails: HLP99

Empfohlener Basispfad: C:\Prototyping\  (oder beliebiger Laufwerksbuchstabe)

  <Laufwerk>:\<Installationspfad>\

  R+MUNI Apps\
      Installationsordner für alle MUNI-Tools (kein GitHub Sync)

  R+MUNI Archiv <Kundenkürzel>\
      Kunden-Archivordner — Backup, Restore, historische Stände

  R+MUNI <Kundenkürzel>\
      R+MUNI Kundenumgebung — Scripts, Modelle, Konfiguration
      root.cfg und structure.txt liegen hier
      GitHub Sync: Kunden-Repo (optional Freigabe DEV für Support)

  R+MUNI Doku <Kundenkürzel>\
      Kundendokumentation
      GitHub Sync: Kunden-Repo (optional Freigabe DEV für Support)
        +---00-governance
        +---01-principles
        +---02-how2
        +---03-roesetta_stone
        +---04-notes
        +---05-backlog
        +---06-sprints
        +---07-creative

  R+MUNI Archi <Kundenkürzel>\
      Kunden-Archimodelle und historische Stände
      GitHub Sync: Kunden-Repo (optional Freigabe DEV für Support)

  R-MUNI\
      GitHub Sync — Blueprint App Repository (öffentlich)
      https://github.com/arch-nullnull/R-MUNI.git

  R-MUNI-Doku-public\
      DEV Doku — öffentliche Entwickler- und Expert-Dokumentation
      https://github.com/arch-nullnull/R-MUNI-Doku-public.git

HINWEIS GitHub Sync:
  Der Kunde hält seine eigenen Repositories — nicht der DEV.
  DEV-Zugriff für Support erfolgt nur auf explizite Freigabe durch den Kunden.
  Damit entscheidet der Kunde selbst ob und auf was der DEV Zugriff hat.


1.2 Blueprint Root-Struktur und root.cfg
--------------------------------------------------------------------------------
  R+MUNI <KUERZEL>\
  ├── Install.txt           ← dieses Dokument
  ├── root.cfg              ← Konfiguration: rootfolder=<Pfad>
  ├── structure.txt         ← Ordnerstruktur-Referenz (Script-Pflicht)
  ├── 00-model\             ← ArchiMate + BPMN Modelle
  ├── 01-artifacts\         ← Scripts, CSVs, XML, XLSX, Reports
  └── 02-stages\            ← Laufzeit-Artefakte, Logs, Archive

  root.cfg prüfen nach Installation:
    Datei    : R+MUNI <KUERZEL>\root.cfg
    Inhalt   : rootfolder=C:\Prototyping\R+MUNI <KUERZEL>
    Anpassen : Bei abweichendem Pfad mit Notepad++ öffnen und anpassen.

8. ENCODING HINWEIS
================================================================================

Alle Dateien im Blueprint müssen UTF-8 sein — ohne BOM empfohlen.
Ausnahme: jira_ea_import.csv (ATL02 Output) mit UTF-8 BOM
          da Jira CSV-Import BOM für korrekte Zeichenerkennung benötigt.

Betrifft besonders:
  Master CSVs  : 01-artifacts\02-csv\00-master\
                 elements.csv, relations.csv, properties.csv
  Mapping      : 01-artifacts\02-csv\01-mapping\csvmapping.txt
                 01-artifacts\00-xml\01-mapping\mapping.txt
  Konfiguration: root.cfg, flowtriggers.txt, flowmapping.txt

Prüfen und konvertieren: Notepad++ → Encoding Menü → UTF-8
Archi Import schlägt bei falschem Encoding ohne klare Fehlermeldung fehl.
