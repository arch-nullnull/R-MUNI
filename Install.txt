1. ÜBERSICHT
--------------------------------------------------------------------------------
R+MUNI läuft auf Windows 11 und Linux ohne Datenbankserver, Webserver oder
Container. Alle Komponenten sind kostenlos und open source.

Entwickelt und getestet auf Windows 11 Enterprise.
Linux kompatibel — alle Scripts verwenden os.path (keine hardcodierten Pfade).
macOS theoretisch kompatibel, nicht offiziell getestet.


1.1 Verzeichnisstruktur (Gesamtüberblick)
  R+MUNI ist in mehrere Verzeichnisse aufgeteilt. Empfohlener Basispfad:
  C:\Prototyping\

  R+MUNI\                  ← Herzstück: Scripts, Modelle, Konfiguration
                              GitHub Sync: PUBLIC
                              structure.txt liegt hier (Pflicht für Scripts)

  R+MUNI Apps\             ← Installationspfad für alle R+MUNI relevanten Tools
                              Kein GitHub Sync

  R+MUNI Archiv\           ← Alte Entwicklungsstände, Script-Fragmente,
                              Sicherungskopien
                              Kein GitHub Sync
                              Zukünftig: Ziel für automatische Backup/Restore Jobs

  R+MUNI Doku\             ← Dokumentation, aufgeteilt in drei Unterordner:
    R+MUNI Doku-creative\     Bilder, Präsentationen, Grafiken
                              GitHub Sync: PRIVATE
    R+MUNI Doku-internal\     Interne Dokus, Backlog, Sprints, Arbeitsdokumente
                              Kein GitHub Sync
    R+MUNI Doku-public\       Offizielle R+MUNI Dokumentation
                              GitHub Sync: PUBLIC

  R+MUNI Installer\        ← Lokale Installer-Sammlung (Offline-Installation)
                              Kein GitHub Sync


1.2 Blueprint Root-Struktur (R+MUNI\)
  R+MUNI\
  ├── Install.txt           ← dieses Dokument
  ├── root.txt              ← BLUEPRINT_ROOT Konfiguration
  ├── structure.txt         ← Ordnerstruktur-Referenz (Script-Pflicht)
  ├── .gitattributes        ← GitHub Sync Konfiguration
  ├── 01-model\             ← ArchiMate + BPMN Modelle
  ├── 02-artifacts\         ← Scripts, CSVs, XML, XLSX, Reports
  └── 03-stages\            ← Laufzeit-Artefakte, Logs, Archive

2.4 Blueprint Ordnerstruktur
  Die Verzeichnisstruktur gemäß structure.txt muss vor dem ersten
  Script-Lauf vollständig vorhanden sein.

  root.txt im Blueprint-Root muss korrekt befüllt sein:
    BLUEPRINT_ROOT=<absoluter oder relativer Pfad>

  Relativer Pfad wird relativ zur Position von root.txt aufgelöst.
  Bei Installation nach C:\Prototyping\R+MUNI ist root.txt bereits
  vorkonfiguriert — kein Anpassungsbedarf.


2.5 Blueprint ZIP — Schnellinstallation
  Datei    : R+MUNI_clean.zip
  Quelle   : GitHub Repository (R+MUNI Releases)
  Inhalt   : Vollständige Ordnerstruktur, alle Scripts, alle Konfigurationen
             Keine Modelle, keine persönlichen Daten ("clean")

  Warum ZIP statt GitHub Clone:
    GitHub kopiert keine leeren Ordner. Die Blueprint-Ordnerstruktur
    enthält viele leere Verzeichnisse die für den Script-Betrieb zwingend
    benötigt werden. Die ZIP löst dieses Problem vollständig.

  Installation Schritt für Schritt:
    1. R+MUNI_clean.zip herunterladen
    2. ZIP entpacken nach C:\Prototyping\R+MUNI
       Ergebnis: C:\Prototyping\R+MUNI\root.txt,
                 C:\Prototyping\R+MUNI\02-artifacts\ usw.
    3. Fertig — root.txt ist bereits vorkonfiguriert.

  Anderes Installationsverzeichnis (z.B. D:\Projekte\MUNI):
    root.txt mit Notepad++ öffnen und anpassen:
      BLUEPRINT_ROOT=D:\Projekte\MUNI
    Speichern. Fertig.

5. ENCODING HINWEIS
--------------------------------------------------------------------------------
Alle Dateien im Blueprint müssen UTF-8 sein — ohne BOM empfohlen.
Ausnahme: jira_ea_import.csv (ATL02 Output) wird mit UTF-8 BOM erzeugt
          da Jira CSV-Import BOM für korrekte Zeichenerkennung benötigt.

Betrifft besonders:
  - Master CSVs:  R+MUNI\02-artifacts\02-csv\00-master\
                  elements.csv, relations.csv, properties.csv
  - Mapping:      R+MUNI\02-artifacts\02-csv\01-mapping\csvmapping.txt
                  R+MUNI\02-artifacts\00-xml\01-mapping\mapping.txt
  - Konfiguration: root.txt, flowtriggers.txt, flowmapping.txt

Prüfen und konvertieren: Notepad++ → Encoding Menü → UTF-8
Oder via Converter Plugin für Batch-Konvertierung.

Archi Import schlägt bei falschem Encoding ohne klare Fehlermeldung fehl.


6. ENTERPRISE UPGRADE-PFADE
--------------------------------------------------------------------------------
R+MUNI ist als KMU-Einstiegslösung konzipiert. Für Organisationen die in
professionelle Enterprise-Plattformen wachsen möchten, gibt es validierte
bzw. dokumentierte Migrationspfade aus dem Blueprint heraus.

Grundprinzip: Die konsequente Einhaltung von BPMN 2.0 und ArchiMate 3.2 Norm
ohne tool-eigene Erweiterungen ist die Voraussetzung für alle Upgrade-Pfade.


6.0 HINWEIS: Tool-Agnostik als Designprinzip
  R+MUNI ist tool-agnostisch. Jedes Tool im Blueprint ist prinzipiell
  austauschbar — vorausgesetzt das Ersatz-Tool unterstützt die jeweilige
  Norm (BPMN 2.0 bzw. ArchiMate 3.2).

  Camunda 7 Community Edition hat im Oktober 2025 sein End-of-Life erreicht.
  Da R+MUNI ausschließlich normkonforme BPMN 2.0 Dateien erzeugt (keine
  Camunda-spezifischen Erweiterungen), können diese mit jedem BPMN 2.0
  kompatiblen Modeler bearbeitet werden — inkl. Camunda Modeler für
  Camunda 8, ADONIS, oder alternativen Open-Source Tools.
  Das EOL von Camunda 7 hat damit keine Auswirkung auf den Blueprint-Betrieb.

  Validiert am 2026-03-07: R+MUNI Artefakte sind direkt in ADONIS und ADOIT
  importierbar — ohne Nachbearbeitung, ohne Konvertierung.


6.1 ADONIS (BOC-Group) — BPMN Migration
  URL      : https://www.boc-group.com/de/adonis/
  Lizenz   : kostenpflichtig (Enterprise)
  Zweck    : Enterprise Business Process Management
  Format   : BPMN 2.0 Import (.bpmn)

  Migration aus R+MUNI:
    R+MUNI BPMN-Dateien (Camunda Modeler, Standard-Export) sind direkt
    in ADONIS importierbar. Kein Tooling-Brückenbedarf, kein Datenverlust.
    Voraussetzung: Strikt normkonforme BPMN 2.0 Modellierung (Blueprint-Standard).


6.2 ADOIT (BOC-Group) — ArchiMate Migration
  URL      : https://www.boc-group.com/de/adoit/
  Lizenz   : kostenpflichtig (Enterprise)
  Zweck    : Enterprise Architecture Management
  Format   : OEF Import (.oef — Open Exchange Format)

  Migration aus R+MUNI:
    R+MUNI ArchiMate-Modelle (Archi 5.x OEF Export) sind direkt
    in ADOIT importierbar. Kein Tooling-Brückenbedarf, kein Datenverlust.
    Voraussetzung: Strikt normkonforme ArchiMate 3.2 Modellierung (Blueprint-Standard).

  Hinweis: Die konsequente Einhaltung von BPMN 2.0 und ArchiMate 3.2 Norm
           ohne tool-eigene Erweiterungen ist nicht nur eine Design-Entscheidung —
           sie ist durch den BOC-Import empirisch validiert (2026-03-07).


6.3 Camunda 8 — BPMN Prozessausführung (Enterprise)
  URL      : https://camunda.com/
  Lizenz   : kostenpflichtig (SaaS oder Self-Hosted)
  Zweck    : Enterprise Process Orchestration und Automatisierung

  Upgrade aus R+MUNI:
    Da R+MUNI ausschließlich normkonforme BPMN 2.0 Modelle erzeugt,
    sind diese direkt im Camunda Modeler für Camunda 8 nutzbar.
    BPMN-Dateien können ohne Anpassung weiterverwendet werden,
    sofern keine Camunda-7-spezifischen Execution-Extensions genutzt wurden
    (Blueprint-Standard: keine tool-eigenen Erweiterungen).
