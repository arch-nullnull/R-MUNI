1.2 Ausloser (gemäss GOV 10.3 / 10.5)
---------------------------------------
Ausloser-Typ : Feature-Zuwachs (Entwicklerwunsch)

Begruendung  : R+MUNI erzeugt vollstaendige ArchiMate HTML Reports ueber die
               native Archi Export-Funktion (File → Report → HTML). Diese
               Reports bestehen aus einem Ordner mit index.html und
               Unterordnern fuer Diagramme, Styles und Skripte.

               Bisher musste der Anwender den Report-Ordner manuell oeffnen
               und index.html im Browser starten. Bei mehreren Modellen war
               kein gleichzeitiger Betrieb moeglich.

               Der Bedarf entstand aus dem Wunsch, Reports lokal ohne
               Cloud-Abhaengigkeit bereitzustellen — erreichbar fuer alle
               Geraete im lokalen Netzwerk ohne externe Dienste oder
               sicherheitsrelevante Serverinfrastruktur.

Fachlicher   : Archi HTML Reports sind vollstaendig interaktiv (navigierbare
Mehrwert       Diagramme, klickbare Elemente, Suchfunktion). Ein lokaler
               Webserver macht diese Interaktivitaet ohne manuellen Aufwand
               zugaenglich — fuer den Anwender selbst und fuer andere
               Geraete im Netz (z.B. Praesentation am Beamer, Kollegen
               im selben WLAN).

Erweiterung  : Auf Basis der Erstimplementierung (Einzelserver) wurde
               sofort eine Mehrmandanten-Faehigkeit entwickelt: Ein
               webconfig.txt gesteuert koennen beliebig viele Reports
               gleichzeitig auf verschiedenen Ports bereitgestellt werden.

Governance-  : HLP09 ist ein additives Hilfsskript. Es veraendert keine
Konformitaet   bestehenden Scripts, Konfigurationsdateien oder Artefakte.
               Stage 3 Freeze wird vollstaendig respektiert.
               Neuer Ordner 05-reports ersetzt den bisherigen 05-images Ordner
               (logische Umbenennung, keine inhaltliche Aenderung).

2. ZIELDEFINITION (gemäss GOV 10.6)
--------------------------------------------------------------------------------

Ziel         : Entwicklung eines Python-Scripts (HLP09-serve_report.py),
               das beliebig viele Archi HTML Reports gleichzeitig als lokale
               Webserver bereitstellt, gesteuert ueber eine externe
               Konfigurationsdatei (webconfig.txt).

Abgrenzung   : HLP09 ist ein reines Hilfsskript (HLP-Serie).
               Es veraendert keine Modelldaten, keine Master CSVs und
               keine XML-Artefakte. Es ist kein Flow-Script.

Ueberpruefbar: Erfolgskriterium ist der gleichzeitige Start mehrerer
               Reports mit korrekter Ausgabe aller URLs (lokal, IP,
               Hostname) sowie korrektem Ueberspringen von Eintraegen
               ohne index.html.

3. TECHNISCHE ENTSCHEIDUNGEN
--------------------------------------------------------------------------------

3.1 Python eingebauter HTTP Server (kein Apache / IIS)
-------------------------------------------------------
Entscheidung : HLP09 verwendet ausschliesslich http.server aus der
               Python Standardbibliothek.

Begruendung  : Kein zusaetzlicher Install, keine Konfiguration, kein
               Sicherheitsrisiko durch dauerhaft laufende Dienste.
               Der Server laeuft nur waehrend das Script aktiv ist.
               Fuer rein lesende HTML-Auslieferung im lokalen Netz
               ist die Standardbibliothek vollstaendig ausreichend.
               Blueprint-Prinzip: keine externen Abhaengigkeiten.

3.2 webconfig.txt als externe Steuerungsdatei
----------------------------------------------
Entscheidung : Alle Report-Konfigurationen werden in einer externen
               webconfig.txt definiert. Das Script selbst enthaelt
               keine hartkodierten Report-Pfade oder Ports.

Begruendung  : Entspricht dem etablierten Blueprint-Muster
               (csvexport.txt, assetsexport.txt, mapping.txt).
               Neue Reports koennen ohne Code-Aenderung hinzugefuegt
               werden. Auskommentieren eines Eintrags deaktiviert
               den Report ohne Loeschen.

Format:
               NAME=Anzeigename
               PATH=relativer/pfad/zum/ordner
               PORT=8080

               Leerzeile trennt Eintraege.
               # kommentiert aus.

3.3 Ordnerstruktur nach Sprache/Welt getrennt
----------------------------------------------
Entscheidung : 05-reports Unterordner sind nach Modellierungssprache
               getrennt, nicht nach Dateiformat:
                 00-archimate/   ArchiMate Reports
                 01-bpmn/        BPMN Reports
                 99-struktur/    Strukturberichte

Begruendung  : Das Dateiformat (HTML, PNG, spaeter ggf. PDF) ist
               sekundaer. Die logische Herkunft (aus welcher Welt
               kommt der Report) ist die relevante Dimension.
               Konsistent mit der bestehenden child-Ordner Logik
               (00-archimatechild, 01-bpmnchild).

3.4 Unterordner pro Modell innerhalb der Welten
------------------------------------------------
Entscheidung : Jedes Modell bekommt einen eigenen Unterordner:
                 00-archimate/MUNI EA Modell/
                 00-archimate/MUNI FLOW/

Begruendung  : Mehrere Modelle derselben Welt koennen gleichzeitig
               bereitgestellt werden ohne sich gegenseitig zu
               ueberschreiben. PATH in webconfig.txt referenziert
               immer den Modell-Unterordner direkt.

3.5 Netzwerk-Ausgabe: Lokal + IP + Hostname
--------------------------------------------
Entscheidung : Das Script gibt beim Start alle drei Zugangswege aus:
                 Lokal     http://localhost:<port>
                 IP        http://192.168.x.x:<port>
                 Hostname  http://RECHNERNAME:<port>

Begruendung  : IP-Adresse kann sich aendern (DHCP). Der Windows-
               Hostname ist stabiler und einfacher zu kommunizieren.
               Beide werden angezeigt damit der Anwender situativ
               entscheiden kann welche URL er weitergibt.

3.6 Ueberspringe-Logik fuer leere Ordner
-----------------------------------------
Entscheidung : Eintraege ohne index.html werden uebersprungen
               (Warnung im Terminal), kein Abbruch.

Begruendung  : Ein noch nicht exportierter Report soll den Start
               aller anderen Reports nicht blockieren. Der Anwender
               sieht klar welche Eintraege uebersprungen wurden
               und warum.

3.7 Umbenennung 05-images zu 05-reports
----------------------------------------
Entscheidung : Der bisherige Ordner 05-images wurde in 05-reports
               umbenannt. Unterordner bleiben erhalten, werden
               aber logisch neu strukturiert.

Begruendung  : "Images" beschreibt das Dateiformat. "Reports"
               beschreibt den Zweck. Da der Ordner bisher nur fuer
               manuelle Exporte genutzt wurde (keine Script-
               Abhaengigkeiten), war die Umbenennung ohne
               Folgeaenderungen moeglich.
