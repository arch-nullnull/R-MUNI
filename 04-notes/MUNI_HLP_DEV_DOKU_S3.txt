================================================================================
  1.  ÜBERSICHT & ARCHITEKTUR
================================================================================

  Die HLP-Serie ist eine Sammlung autarker Python-Hilfsskripte für die MUNI App.
  Jedes Script erfüllt genau eine Aufgabe (Single Responsibility), schreibt
  ein eigenes Log und ist ohne externe Abhängigkeiten ausführbar — abgesehen
  von der gemeinsamen Root-Auflösung, die in jedem Script identisch eingebaut
  ist.

  Designziele
  ───────────
  · OS-agnostisch        Windows, macOS, Linux — keine Plattformspezifika
  · Keine Pip-Deps       Ausschliesslich Python Standard Library
  · Autark               Jedes Script läuft standalone, kein gemeinsames Modul
  · Nachvollziehbar      Jede Operation wird ins Log geschrieben
  · Erweiterbar          Neue HLP-Scripts folgen demselben Muster

  Technische Basis
  ────────────────
  · Sprache    :  Python 3.10+
  · Bibliothek :  os, sys, shutil, zipfile, hashlib, json, platform,
                  datetime, argparse  (alles Standard Library)
  · Encoding   :  UTF-8 durchgehend

  Script-Übersicht
  ────────────────
  ┌────────┬──────────────────────────────────┬──────────────────────────────┐
  │ Script │ Name                             │ Aufgabe                      │
  ├────────┼──────────────────────────────────┼──────────────────────────────┤
  │ HLP00  │ HLP00_resolve_root.py            │ Root auflösen, Log schreiben │
  │ HLP01  │ HLP01_copy.py                    │ Kopieren (Quelle bleibt)     │
  │ HLP02  │ HLP02_move.py                    │ Verschieben (Quelle löschen) │
  │ HLP03  │ HLP03_clean.py                   │ Ordnerinhalt löschen         │
  │ HLP04  │ HLP04_dirlog.py                  │ Verzeichnisbaum ins Log      │
  │ HLP05  │ HLP05_context_structure.py       │ context.json + structure.json│
  │ HLP06  │ HLP06_backup.py                  │ ZIP-Backup mit Manifest      │
  │ HLP07  │ HLP07_restore.py                 │ Backup wiederherstellen      │
  └────────┴──────────────────────────────────┴──────────────────────────────┘

================================================================================
  3.  GEMEINSAME DESIGN-PRINZIPIEN
================================================================================

  3.1  Root-Auflösung
  ───────────────────
  Jedes Script beginnt mit dieser identischen Codezeile:

      ROOT = os.path.dirname(os.path.abspath(__file__))

  __file__ ist der absolute Pfad des Scripts selbst. Damit ist ROOT immer
  das Verzeichnis, in dem die HLP-Scripts liegen — unabhängig davon, von
  wo aus das Script aufgerufen wird.

  Beispiel:
      Aufruf aus C:\Users\dev>  python D:\muni\HLP01_copy.py a b
      → ROOT = D:\muni
      → alle relativen Pfade werden von D:\muni aus aufgelöst

  3.2  Pfadauflösung
  ──────────────────
  Alle Scripts nutzen diese Hilfsfunktion:

      def abs_path(p: str) -> str:
          return p if os.path.isabs(p) else os.path.join(ROOT, p)

  Absolute Pfade werden unverändert durchgereicht.
  Relative Pfade werden relativ zu ROOT aufgelöst.

  3.3  Logging-Muster
  ───────────────────
  Jedes Script schreibt in eine eigene Log-Datei unter logs/.
  Das Log-Muster ist in jedem Script identisch:

      def log(msg: str):
          os.makedirs(os.path.dirname(LOG_FILE), exist_ok=True)
          with open(LOG_FILE, "a", encoding="utf-8") as f:
              f.write(f"[{timestamp()}] {msg}\n")
          print(f"[{timestamp()}] {msg}")

  · Appending (a-Mode): Logs werden nie überschrieben, nur erweitert
  · Gleichzeitig Konsole und Datei
  · Timestamp-Format: YYYY-MM-DD HH:MM:SS

  3.4  Fehlerbehandlung
  ─────────────────────
  · Fehlende Quellpfade → log + sys.exit(1)
  · Einzelne Dateifehler bei Batch-Operationen → log + weiter (kein Abbruch)
  · PermissionError → log + skip, wird gezählt

  3.5  CLI-Argumente
  ──────────────────
  Scripts mit mehreren Optionen nutzen argparse.
  Scripts mit einfachen Pfad-Argumenten nutzen sys.argv direkt.

================================================================================
  5.  HLP01 — COPY SCRIPT
================================================================================

  Datei    :  HLP01_copy.py
  Aufgabe  :  Kopiert eine Datei oder einen Ordner von Quelle nach Ziel.
              Die Quelldatei / der Quellordner bleibt unverändert bestehen.
  Log      :  logs/HLP01_copy.log

  Verwendung
  ──────────
      python HLP01_copy.py <quelle> <ziel>

  Beispiele
  ─────────
      python HLP01_copy.py data/config.json backup/config.json
      python HLP01_copy.py assets/          deploy/assets/
      python HLP01_copy.py /abs/pfad/a.txt  /abs/pfad/b.txt

  Verhalten nach Typ
  ──────────────────
  ┌──────────────────┬───────────────────────────────────────────────────┐
  │ Quelltyp         │ Verhalten                                         │
  ├──────────────────┼───────────────────────────────────────────────────┤
  │ Datei → Datei    │ shutil.copy2() — kopiert inkl. Metadaten          │
  │ Datei → Ordner   │ Datei wird in den Zielordner kopiert              │
  │ Ordner → Ordner  │ shutil.copytree() — rekursiv, Ziel wird ersetzt   │
  └──────────────────┴───────────────────────────────────────────────────┘

  Ablaufdiagramm
  ──────────────

      START
        │
        ▼
      Quelle existiert?
        │
        ├─ NEIN ──→ log FEHLER + sys.exit(1)
        │
        ▼ JA
      Zielordner erstellen (falls nicht vorhanden)
        │
        ▼
      Datei oder Ordner?
        │
        ├─ Datei ──→ shutil.copy2(src, dst)
        │
        └─ Ordner ─→ shutil.copytree(src, dst)
        │
        ▼
      log [COPY] + [OK]
        │
        ▼
      ENDE

  Wichtige Hinweise
  ─────────────────
  · shutil.copy2 überträgt auch Zeitstempel und Berechtigungen
  · Bei copytree: existierender Zielordner wird zuerst gelöscht (rmtree)
  · Metadaten (Änderungszeit etc.) bleiben erhalten


================================================================================
  6.  HLP02 — MOVE SCRIPT
================================================================================

  Datei    :  HLP02_move.py
  Aufgabe  :  Verschiebt eine Datei oder einen Ordner. Die Quelle wird nach
              erfolgreichem Verschieben gelöscht.
  Log      :  logs/HLP02_move.log

  Verwendung
  ──────────
      python HLP02_move.py <quelle> <ziel>

  Beispiele
  ─────────
      python HLP02_move.py temp/report.pdf output/report.pdf
      python HLP02_move.py staging/        live/
      python HLP02_move.py old_name.txt    new_name.txt

  Kernfunktion
  ────────────
  Intern wird shutil.move() verwendet. Diese Funktion ist OS-agnostisch:

  · Auf demselben Dateisystem    →  atomares Rename (sehr schnell)
  · Über Dateisystemgrenzen      →  kopieren + löschen (automatisch)
  · Ordner                       →  rekursiv mit allen Inhalten

  Ablaufdiagramm
  ──────────────

      START
        │
        ▼
      Quelle existiert?
        │
        ├─ NEIN ──→ log FEHLER + sys.exit(1)
        │
        ▼ JA
      Zielordner erstellen (falls nicht vorhanden)
        │
        ▼
      shutil.move(src, dst)
        │
        ▼
      log [MOVE] "src → dst"
        │
        ▼
      log [OK] "Quelldatei gelöscht"
        │
        ▼
      ENDE

  Unterschied zu HLP01
  ────────────────────
  ┌──────────────┬────────────────────────────────────────────────────┐
  │              │ HLP01 Copy         │ HLP02 Move                    │
  ├──────────────┼────────────────────┼───────────────────────────────┤
  │ Quelle nach  │ Bleibt bestehen    │ Wird gelöscht                 │
  │ Operation    │                    │                               │
  │ Intern       │ shutil.copy2 /     │ shutil.move                   │
  │              │ shutil.copytree    │                               │
  │ Rückgängig   │ Ja (Quelle da)     │ Nein (Quelle weg)             │
  └──────────────┴────────────────────┴───────────────────────────────┘


================================================================================
  7.  HLP03 — CLEANER
================================================================================

  Datei    :  HLP03_clean.py
  Aufgabe  :  Löscht den gesamten Inhalt eines oder mehrerer Ordner.
              Die Ordner selbst bleiben bestehen — nur ihr Inhalt wird entfernt.
  Log      :  logs/HLP03_clean.log

  Verwendung
  ──────────
      python HLP03_clean.py <ordner> [<ordner2> <ordner3> ...]

  Beispiele
  ─────────
      python HLP03_clean.py cache
      python HLP03_clean.py temp output logs
      python HLP03_clean.py /abs/pfad/cache  relative/temp

  Verhalten
  ─────────
  · Alle Dateien und Unterordner im angegebenen Ordner werden entfernt
  · Der Ordner selbst wird NICHT gelöscht
  · Dateien:   os.remove()
  · Symlinks:  os.remove()
  · Ordner:    shutil.rmtree() (rekursiv)
  · Fehler bei einzelnen Einträgen → log + weitermachen (kein Abbruch)

  Beispielausgabe
  ───────────────
      [2026-03-01 14:30:22] ══════════════  Start HLP03 Clean
      [2026-03-01 14:30:22]   [DEL-F]  /muni/cache/temp1.tmp
      [2026-03-01 14:30:22]   [DEL-F]  /muni/cache/session.db
      [2026-03-01 14:30:22]   [DEL-D]  /muni/cache/img_cache
      [2026-03-01 14:30:22]   [OK]  /muni/cache bereinigt — 2 Datei(en), 1 Unterordner, 0 Fehler
      [2026-03-01 14:30:22] ══════════════  Ende HLP03 Clean

  Vorsicht
  ────────
  ⚠  Diese Operation ist NICHT rückgängig zu machen.
     Vor dem Ausführen sicherstellen, dass der richtige Ordner angegeben ist.
     Im Zweifelsfall vorher HLP06 (Backup) ausführen.

  8.  HLP04 — DIRECTORY LOGGER
================================================================================

  Datei    :  HLP04_dirlog.py
  Aufgabe  :  Scannt einen oder mehrere Ordner rekursiv und schreibt den
              vollständigen Verzeichnisbaum mit Dateigrößen ins Log.
  Log      :  logs/HLP04_dirlog.log

  Verwendung
  ──────────
      python HLP04_dirlog.py <ordner> [<ordner2> ...]
      python HLP04_dirlog.py .                          ← aktuelles Verzeichnis
      python HLP04_dirlog.py data output assets

  Ausgabeformat (Beispiel)
  ────────────────────────

      ════════════════════════════════════════════════════════════
        HLP04 – Directory Log  |  2026-03-01 14:30:22
      ════════════════════════════════════════════════════════════

      ────────────────────────────────────────────────────────────
        Ordner : /home/user/muni/data
        Scan   : 2026-03-01 14:30:22
      ────────────────────────────────────────────────────────────
        📁 ./
           📄 config.json  (2.1 KB)
           📄 readme.txt   (0.8 KB)
           📁 assets/
              📄 logo.png  (45.3 KB)
              📄 icon.svg  (3.2 KB)
              📁 fonts/
                 📄 main.ttf  (128.0 KB)

        Gesamt : 5 Datei(en), 179.4 KB
      ════════════════════════════════════════════════════════════  Ende

  Größenformatierung
  ──────────────────
  Die Dateigrößen werden automatisch in die passende Einheit umgewandelt:

      < 1024 Byte    →  B
      < 1024 KB      →  KB
      < 1024 MB      →  MB
      ≥ 1024 MB      →  GB

  Einsatzzweck
  ────────────
  · Inventarisierung von Projektordnern
  · Vor/nach Vergleich (zwei Log-Einträge vergleichen)
  · Dokumentation des Deployment-Zustands
  · Debugging: prüfen ob alle erwarteten Dateien vorhanden sind

  9.  HLP05 — CONTEXT & STRUCTURE
================================================================================

  Datei    :  HLP05_context_structure.py
  Aufgabe  :  Erstellt zwei JSON-Dateien: context.json (Metadaten/Umgebung)
              und structure.json (vollständiger Dateibaum als JSON).
  Output   :  context/context.json   und   context/structure.json
  Log      :  logs/HLP05_context.log

  Verwendung
  ──────────
      python HLP05_context_structure.py                   ← Root scannen
      python HLP05_context_structure.py data              ← Unterordner scannen
      python HLP05_context_structure.py --context-only    ← nur context.json
      python HLP05_context_structure.py --structure-only  ← nur structure.json

  9.1  context.json
  ─────────────────
  Enthält Metadaten über die Umgebung zum Zeitpunkt der Erstellung.

  Struktur:

      {
        "meta": {
          "generated_by": "HLP05_context_structure.py",
          "generated_at": "2026-03-01 14:30:22",
          "version": "1.0.0"
        },
        "environment": {
          "os": "Windows 10",
          "architecture": "AMD64",
          "python": "3.11.2",
          "hostname": "DEV-PC-01"
        },
        "paths": {
          "root": "C:\\muni",
          "context_dir": "C:\\muni\\context",
          "context_file": "C:\\muni\\context\\context.json",
          "structure_file": "C:\\muni\\context\\structure.json",
          "log_file": "C:\\muni\\logs\\HLP05_context.log",
          "cwd": "C:\\Users\\dev"
        },
        "app": {
          "name": "MUNI",
          "description": "MUNI App – Helper Script Context",
          "note": "Automatisch generiert von HLP05."
        }
      }

  9.2  structure.json
  ───────────────────
  Enthält den vollständigen Dateibaum als verschachteltes JSON-Objekt.

  Struktur:

      {
        "meta": {
          "generated_by": "HLP05_context_structure.py",
          "generated_at": "2026-03-01 14:30:22",
          "scan_root": "C:\\muni"
        },
        "tree": {
          "name": "muni",
          "type": "directory",
          "file_count": 2,
          "dir_count": 1,
          "children": [
            {
              "name": "HLP00_resolve_root.py",
              "type": "file",
              "size": "2.3 KB",
              "bytes": 2312
            },
            {
              "name": "logs",
              "type": "directory",
              "file_count": 1,
              "dir_count": 0,
              "children": [
                {
                  "name": "HLP00_root.log",
                  "type": "file",
                  "size": "0.4 KB",
                  "bytes": 412
                }
              ]
            }
          ]
        }
      }

  Ausgeschlossene Ordner (Standard)
  ──────────────────────────────────
  .git  |  __pycache__  |  .venv  |  node_modules  |  .idea

  Diese werden beim Scan übersprungen und erscheinen nicht in structure.json.

  Einsatzzweck
  ────────────
  · Snapshot der Umgebung vor einem grossen Eingriff
  · Maschinell lesbare Dokumentation (z.B. für andere Tools)
  · Versionierbare Strukturdokumentation (structure.json ins Repo)
  · Vergleich zweier Zustände durch Diff zweier structure.json

  10. HLP06 — BACKUP
================================================================================

  Datei    :  HLP06_backup.py
  Aufgabe  :  Erstellt ein vollständiges, timestamptes ZIP-Backup des
              angegebenen Ordners inkl. eingebettetem Manifest.
  Output   :  <dest>/MUNI_backup_YYYYMMDD_HHMMSS.zip
  Log      :  logs/HLP06_backup.log

  Verwendung
  ──────────
      python HLP06_backup.py
      python HLP06_backup.py --dest D:/backups
      python HLP06_backup.py --src  data
      python HLP06_backup.py --src  data --dest /mnt/nas/backups
      python HLP06_backup.py --exclude cache temp .env
      python HLP06_backup.py --no-checksums

  Parameter
  ─────────
  ┌────────────────┬─────────────┬────────────────────────────────────────┐
  │ Argument       │ Standard    │ Beschreibung                           │
  ├────────────────┼─────────────┼────────────────────────────────────────┤
  │ --src          │ ROOT        │ Quellordner der gesichert wird         │
  │ --dest         │ ROOT/backups│ Zielordner für das ZIP-Archiv          │
  │ --exclude      │ (leer)      │ Zusätzliche Namen zum Ausschliessen    │
  │ --no-checksums │ (nicht ges.)│ SHA-256 Berechnung überspringen        │
  └────────────────┴─────────────┴────────────────────────────────────────┘

  Standard-Ausschlüsse (immer aktiv)
  ───────────────────────────────────
  .git  |  __pycache__  |  .venv  |  venv  |  node_modules
  .idea  |  .vscode  |  .DS_Store  |  Thumbs.db

  Archiv-Struktur
  ───────────────

      MUNI_backup_20260301_143022.zip
      │
      ├── manifest.json          ← Metadaten + Dateiliste + SHA-256 Hashes
      │
      └── backup/                ← alle gesicherten Dateien
          ├── HLP00_resolve_root.py
          ├── HLP01_copy.py
          ├── ...
          ├── context/
          │   ├── context.json
          │   └── structure.json
          └── logs/
              └── HLP00_root.log

  manifest.json Struktur
  ──────────────────────

      {
        "manifest_version": "1.0",
        "tool": "HLP06_backup.py",
        "restore_tool": "HLP07_restore.py",
        "created_at": "2026-03-01 14:30:22",
        "zip_name": "MUNI_backup_20260301_143022.zip",
        "source_root": "/home/user/muni",
        "platform": {
          "os": "Linux",
          "release": "6.1.0",
          "machine": "x86_64",
          "python": "3.11.2",
          "hostname": "dev-server"
        },
        "stats": {
          "file_count": 12,
          "total_size": "48.3 KB",
          "total_bytes": 49459
        },
        "exclude_list": [".git", "__pycache__", "..."],
        "files": [
          {
            "path": "HLP00_resolve_root.py",
            "size_bytes": 1204,
            "size_human": "1.2 KB",
            "sha256": "a3f2b1c4d5e6..."
          },
          ...
        ]
      }

  Ablaufdiagramm
  ──────────────

      START
        │
        ▼
      Quellordner prüfen
        │
        ├─ nicht vorhanden ──→ log FEHLER + exit(1)
        │
        ▼ OK
      Zielordner erstellen
        │
        ▼
      Dateien rekursiv sammeln (collect_files)
      Ausschlüsse herausfiltern
        │
        ▼
      Manifest bauen
      SHA-256 pro Datei berechnen (wenn --no-checksums nicht gesetzt)
        │
        ▼
      ZIP öffnen (ZIP_DEFLATED, Level 6)
        │
        ├──→ backup/<rel_pfad>  für jede Datei
        └──→ manifest.json      als letzter Eintrag
        │
        ▼
      Statistiken loggen
        │
        ▼
      ENDE

  ZIP-Kompression
  ───────────────
  · Algorithmus: ZIP_DEFLATED (Standard ZIP Kompression)
  · Level: 6 (Kompromiss aus Geschwindigkeit und Kompressionsrate)
  · Level 1 = schnell, wenig komprimiert
  · Level 9 = langsam, maximal komprimiert


================================================================================
  11. HLP07 — RESTORE
================================================================================

  Datei    :  HLP07_restore.py
  Aufgabe  :  Stellt ein von HLP06 erstelltes Backup wieder her.
              Liest manifest.json aus dem ZIP, prüft SHA-256 Checksums.
  Log      :  logs/HLP07_restore.log

  Verwendung
  ──────────
      python HLP07_restore.py <backup.zip>
      python HLP07_restore.py backup.zip --dest ./recovered
      python HLP07_restore.py backup.zip --dry-run
      python HLP07_restore.py backup.zip --verify-only
      python HLP07_restore.py backup.zip --dest . --no-verify

  Parameter
  ─────────
  ┌────────────────┬───────────────────────────────────────────────────────┐
  │ Argument       │ Beschreibung                                          │
  ├────────────────┼───────────────────────────────────────────────────────┤
  │ backup         │ Pfad zum ZIP-Archiv (Pflichtargument)                 │
  │ --dest         │ Zielordner (Standard: Original-Pfad aus Manifest)     │
  │ --dry-run      │ Nur simulieren, keine Dateien schreiben               │
  │ --verify-only  │ Nur SHA-256 bereits vorhandener Dateien prüfen        │
  │ --no-verify    │ Checksum-Prüfung nach Restore überspringen            │
  └────────────────┴───────────────────────────────────────────────────────┘

  Ablaufdiagramm
  ──────────────

      START
        │
        ▼
      ZIP existiert?
        │
        ├─ NEIN ──→ log FEHLER + exit(1)
        │
        ▼ JA
      manifest.json aus ZIP laden
        │
        ├─ nicht vorhanden ──→ log FEHLER + exit(1)
        │
        ▼ OK
      Manifest-Info ausgeben (Datum, Quelle, Dateizahl)
        │
        ▼
      --verify-only?
        │
        ├─ JA ──→ SHA-256 aller Dateien im Zielordner prüfen → ENDE
        │
        ▼ NEIN
      --dest angegeben?
        │
        ├─ JA  ──→ restore_root = dest
        └─ NEIN ──→ restore_root = manifest["source_root"]
        │
        ▼
      --dry-run?
        │
        ├─ JA ──→ alle Pfade loggen, nichts schreiben → ENDE
        │
        ▼ NEIN
      Dateien aus backup/* extrahieren
      Zielordner pro Datei erstellen (makedirs)
        │
        ▼
      --no-verify?
        │
        ├─ JA  ──→ fertig
        └─ NEIN ──→ SHA-256 aller Dateien prüfen
        │
        ▼
      Ergebnis loggen (OK / FEHLER / MISMATCH)
        │
        ▼
      ENDE

  Checksum-Verifikation
  ──────────────────────
  Nach dem Restore wird jede Datei gegen den SHA-256 Hash im Manifest
  geprüft. Mögliche Ergebnisse pro Datei:

  ✓ OK       :  Hash stimmt überein — Datei integer
  MISSING    :  Datei fehlt im Zielordner
  MISMATCH   :  Hash weicht ab — Datei beschädigt oder verändert

  OS-Pfad-Kompatibilität
  ──────────────────────
  Im Manifest werden alle Pfade mit Forward Slash (/) gespeichert.
  Beim Restore werden sie mit os.sep in den nativen Pfadtrenner
  des Zielsystems konvertiert:

      manifest:  "context/context.json"
      Windows:   context\context.json
      Linux/Mac: context/context.json

  Damit funktioniert ein auf Linux erstelltes Backup auch auf Windows
  und umgekehrt.

  Typische Restore-Szenarien
  ──────────────────────────

  Szenario A – Standard-Restore (gleicher Ort):
      python HLP07_restore.py backups/MUNI_backup_20260301_143022.zip

  Szenario B – Restore in anderen Ordner (Parallelinstallation):
      python HLP07_restore.py backup.zip --dest /tmp/muni_recovered

  Szenario C – Nur prüfen ob Backup valide ist (nichts schreiben):
      python HLP07_restore.py backup.zip --dry-run

  Szenario D – Bereits wiederhergestellte Dateien nachträglich prüfen:
      python HLP07_restore.py backup.zip --dest ./recovered --verify-only

  Szenario E – Schneller Restore ohne Checksumprüfung:
      python HLP07_restore.py backup.zip --dest ./recovered --no-verify

  13. LOG-ÜBERSICHT
================================================================================

  Alle Log-Dateien liegen unter logs/ relativ zu ROOT.
  Sie werden im Append-Modus geschrieben — jede Ausführung wird hinzugefügt,
  ältere Einträge bleiben erhalten.

  ┌──────────────────────────────┬──────────────────────────────────────┐
  │ Log-Datei                    │ Geschrieben von                      │
  ├──────────────────────────────┼──────────────────────────────────────┤
  │ logs/HLP00_root.log          │ HLP00_resolve_root.py                │
  │ logs/HLP01_copy.log          │ HLP01_copy.py                        │
  │ logs/HLP02_move.log          │ HLP02_move.py                        │
  │ logs/HLP03_clean.log         │ HLP03_clean.py                       │
  │ logs/HLP04_dirlog.log        │ HLP04_dirlog.py                      │
  │ logs/HLP05_context.log       │ HLP05_context_structure.py           │
  │ logs/HLP06_backup.log        │ HLP06_backup.py                      │
  │ logs/HLP07_restore.log       │ HLP07_restore.py                     │
  └──────────────────────────────┴──────────────────────────────────────┘

  Log-Format
  ──────────
  [YYYY-MM-DD HH:MM:SS]  [LEVEL/TAG]  Nachricht

  Beispiele:
      [2026-03-01 14:30:22] [COPY]   data/a.txt → backup/a.txt
      [2026-03-01 14:30:22] [OK]     Copy abgeschlossen.
      [2026-03-01 14:30:22] [FEHLER] Quelle nicht gefunden: /muni/xyz
      [2026-03-01 14:30:22] [SKIP]   Ordner nicht gefunden: cache
      [2026-03-01 14:30:22] [WARN]   Ordner nicht gefunden, benutze ROOT
      [2026-03-01 14:30:22] [DRY]    würde schreiben: /muni/file.txt
      [2026-03-01 14:30:22] [+]      HLP01_copy.py  (1.8 KB)
      [2026-03-01 14:30:22] [!]      SKIP config.env – PermissionError

  Log-Pflege
  ──────────
  Die Logs wachsen mit jeder Ausführung. Für regelmässigen Betrieb empfiehlt
  sich ein periodisches Bereinigen mit HLP03:

      python HLP03_clean.py logs


================================================================================
  14. ERWEITERUNGSHINWEISE
================================================================================

  So wird ein neues HLP-Script korrekt erstellt:

  14.1  Namensschema
  ──────────────────
  HLPXX_beschreibung.py

  · XX  = zweistellige Nummer  (08, 09, 10, ...)
  · beschreibung = kurzes englisches Verb oder Nomen (lowercase)

  Beispiele:  HLP08_compress.py  |  HLP09_sync.py  |  HLP10_report.py

  14.2  Pflicht-Bestandteile
  ──────────────────────────

  Jedes neue Script MUSS diese Elemente enthalten:

  (1) Root-Auflösung (erste Zeile nach Imports):
      ROOT = os.path.dirname(os.path.abspath(__file__))

  (2) Log-Datei-Definition:
      LOG_FILE = os.path.join(ROOT, "logs", "HLPXX_name.log")

  (3) timestamp()-Funktion (identisch zu bestehenden Scripts)

  (4) log()-Funktion (identisch zu bestehenden Scripts, append-Modus)

  (5) abs_path()-Funktion (identisch zu bestehenden Scripts)

  (6) Docstring am Anfang mit:
      - Dateiname
      - Aufgabe
      - Verwendung (CLI-Beispiele)

  14.3  Template für neue Scripts
  ────────────────────────────────

      """
      HLPXX – Kurzbeschreibung
      MUNI App Helper Scripts

      Verwendung:
          python HLPXX_name.py <arg1> [<arg2>]
      """

      import os
      import sys
      import datetime

      ROOT     = os.path.dirname(os.path.abspath(__file__))
      LOG_FILE = os.path.join(ROOT, "logs", "HLPXX_name.log")

      def timestamp(fmt="%Y-%m-%d %H:%M:%S"):
          return datetime.datetime.now().strftime(fmt)

      def log(msg: str):
          os.makedirs(os.path.dirname(LOG_FILE), exist_ok=True)
          with open(LOG_FILE, "a", encoding="utf-8") as f:
              f.write(f"[{timestamp()}] {msg}\n")
          print(f"[{timestamp()}] {msg}")

      def abs_path(p: str) -> str:
          return p if os.path.isabs(p) else os.path.join(ROOT, p)

      def main():
          # ... Logik hier ...
          pass

      if __name__ == "__main__":
          main()

  14.4  Was NICHT getan werden soll
  ──────────────────────────────────
  · Keine externen Bibliotheken (pip install ...)
  · Kein gemeinsames Modul / keine shared imports zwischen Scripts
  · Keine globalen Seiteneffekte beim Import
  · Kein hardcodierter Pfad ausserhalb von ROOT-Auflösung
  · Kein stilles Versagen — jeder Fehler muss geloggt werden


================================================================================
  15. FEHLERBEHANDLUNG & EXIT-CODES
================================================================================

  Exit-Codes
  ──────────
  ┌───────────┬──────────────────────────────────────────────────────────┐
  │ Exit-Code │ Bedeutung                                                │
  ├───────────┼──────────────────────────────────────────────────────────┤
  │     0     │ Erfolg — alles OK                                        │
  │     1     │ Fehler — Quelle nicht gefunden, Archiv fehlt, etc.       │
  └───────────┴──────────────────────────────────────────────────────────┘

  Verhalten bei Fehlern
  ──────────────────────

  Kritische Fehler (Script bricht ab):
  · Quellpfad existiert nicht          → log [FEHLER] + sys.exit(1)
  · Backup-ZIP nicht gefunden          → log [FEHLER] + sys.exit(1)
  · Kein manifest.json im ZIP          → log [FEHLER] + sys.exit(1)
  · Falsches Argument / fehlend        → argparse-Hilfe + exit(2)

  Nicht-kritische Fehler (Script läuft weiter):
  · Einzelne Datei nicht lesbar        → log [!] SKIP + weitermachen
  · PermissionError bei einer Datei    → log [!] SKIP + Fehlerzähler +1
  · Ordner in HLP04 nicht gefunden     → log [SKIP] + nächster Ordner

  Checksum-Fehler in HLP07:
  · MISSING  →  Datei fehlt komplett im Zielordner
  · MISMATCH →  Datei vorhanden aber Hash stimmt nicht
  → Beide werden gezählt und am Ende zusammengefasst geloggt
  → Das Script bricht deswegen NICHT ab (nur Warnung)

  Fehlerdiagnose-Workflow
  ───────────────────────

      Problem aufgetreten?
           │
           ▼
      1.  HLP00 ausführen → prüfen ob ROOT korrekt aufgelöst wird
           │
           ▼
      2.  Zugehöriges Log öffnen (logs/HLPXX_*.log)
           │
           ▼
      3.  Nach [FEHLER] oder [!] Einträgen suchen
           │
           ▼
      4.  Pfade prüfen: absolut oder relativ zu ROOT?
           │
           ▼
      5.  Falls Backup betroffen: HLP07 --dry-run ausführen
          → zeigt was wiederhergestellt würde ohne zu schreiben
